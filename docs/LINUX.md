# Linux 启动

本分支新增 KDE Plasma X11 / XWayland 支持，详见 [KDE 运行说明](KDE.md)。各桌面入口分开、共享 Linux 数据与生命周期：

| 桌面 | 入口 |
| --- | --- |
| niri 原生 Wayland | `.venv/bin/python run_niri.py` |
| KDE X11 / XWayland | `.venv/bin/python run_kde.py` |

`run_linux.py` 保留自动识别和 `--desktop kde` / `--desktop niri`，兼容已有配置；专用入口固定自己的后端。KDE 不需要 niri 或其窗口规则。以下 niri 专用步骤及历史验收记录保留原适用范围。

当前入口针对 CachyOS / niri 原生 Wayland，使用原人物、气泡和界面组件。Windows 入口及 app 源码沿用上游；Linux 平台适配集中在 linux_app/。这是日常持续运行入口，不表示所有 Linux 功能均已移植完成。下方各阶段测试数量与“本轮”记录保留历史范围，最新安装包验证以本版发布说明为准。

## 启动与退出

项目独立 `.venv` 已使用 Python 3.12 配置完成：

```sh
cd ~/forks/codex-bailong-desktop-pet
.venv/bin/python run_linux.py
```

PyCharm 选择「桌宠 Linux」，解释器为项目 `.venv/bin/python`，脚本为 `run_linux.py`，参数留空。停止旧的验证实例后再运行。入口没有运行时限、演示额度、自动移动或自动截图；通过桌宠托盘/右键菜单退出，终端可按 Ctrl+C。SIGTERM 也会执行窗口与后台线程清理。同一数据目录只允许一个正式实例。

当前预览版已接入拖动时气泡持续跟随：原生拖动期间由附着角色的透明 popup 显示原气泡，内容每 100ms 刷新，位置由合成器随角色移动，边缘翻转沿用原布局。松手后跟随画布继续显示约 700ms，等待真实气泡定位后交回可交互控件；分离气泡保持独立。持续拎起及松手落地沿用原逻辑，本机用户已确认中部持续跟随和屏幕边缘表现正常。附着的设置/聊天页在拖动期间也使用原上下避让规则；托盘和胶囊打开设置后的触边返回已通过本机基本验收。托盘菜单保持菜单项身份，修复首次小框、再次空白需滚动的问题；首次、再次打开及菜单操作已获用户确认。

## 自主走动

自由走动沿用原项目的触发时机、速度、移动范围、水平走动开关和动画选择；通常在待机动画结束且没有高优先级任务时按原调度选择走动，不会启动后立即持续移动。右键菜单或设置中的自主走动开关可暂停/恢复，锁定位置会同时禁止移动。首次升级使用 `linux_wandering_ready` 标记开启此前被 Linux 入口关闭的选项，后续重启不会覆盖用户暂停选择。

Linux 层将程序化移动合并为每秒最多约 30 次 niri 请求，每次增量基于已确认的窗口位置。位移目标限制在当前输出可用区域，整个人物画布不能越界；鼠标按下会停止走动并清除排队目标，之后沿用已验收的原生拖动路径。气泡继续跟随实际布局。后台没有逐帧启动 niri 子进程，停止移动后请求计时器停止。

当前原始素材没有独立 `moveAnimations`，所以按原代码回退到 `dragAnimation`，自由移动时看起来像被拎着走；这不是 Linux 新选择的动作。没有修改 Windows 代码或替换动画素材。

本机实测：两分钟采样记录到实际走动，气泡布局差值中位数为 0、最大约 2 逻辑像素，异步操作连接采样峰值 1。另一次原生窗口验证中，角色从 `(832,425)` 走到 `(958,343)` 时模拟鼠标按下，走动和排队目标立即清除，后续两次采样位置均保持 `(958,343)`；极端目标被约束到 `(0,0)` 和 `(1664,824)`，256×256 画布完整留在 1920×1080 输出内。真实拖动已有前序人工验证，本轮走动中按下的精确停位断言使用应用事件注入，不能代替所有输入设备和跨屏人工验收。

源码入口根据人物当前帧、翻转与大小生成 `alpha >= 12` 的逻辑像素输入区域。阈值转换与 KDE 共用 `linux_app/input_shape.py`，niri 通过原生 Wayland `QWindow.setMask` 设置输入区域，不调用 QWidget 的视觉裁剪，保留人物柔和透明边缘。普通透明角落允许点击下层窗口；鼠标按住及原生拖动期间保留完整输入范围，松手后恢复轮廓，以维持已有 Enter/Leave 拖动交接。整窗鼠标穿透设置仍优先。

## 登录图形桌面后自启动

Linux 源码入口的设置 → 开机启动使用 systemd 用户服务。启用并应用后生成 `${XDG_CONFIG_HOME:-~/.config}/systemd/user/bailong.service`，随 `graphical-session.target` 启动、注销桌面时停止；正常退出不重启，异常退出最多在一分钟内尝试启动三次。不需要 root 或 linger。关闭开关只取消下次登录启动，不退出当前桌宠。“随 Codex 启动”使用下述独立监听服务，与此开关分别管理。

服务记录源码虚拟环境或便携程序的绝对路径及当前 `--codex-home`、`--codex-cli`、`--data-dir`，不保存认证内容和本次会话的 socket。每次登录自动选择 niri/KDE；桌面会话须向 systemd 用户管理器导入图形环境。现有手工管理的同名服务不会被覆盖。

AppImage 启动时从 `APPIMAGE` 获取外部文件路径，并确认当前程序位于对应 `APPDIR`；不把临时挂载路径登记为服务。源码虚拟环境、便携目录或 AppImage 移动后，请从新位置启动，关闭并重新开启自启动。linux-preview.2 包含此功能；两个开关互不依赖，关闭“开机启动”不影响独立的 Codex 监听服务。

查看状态和日志：

```sh
systemctl --user is-enabled bailong.service
systemctl --user status bailong.service
journalctl --user -u bailong.service -b
```

本机已用独立临时服务实测启用、带特殊字符的 ExecStart、执行和禁用，测试服务已清理；未通过注销/重新登录进行完整会话验收。实现功能本身不默认开启日常自启动。

## 随 Codex 启动

源码版设置 → Codex → 随 Codex 启动，打开并应用后启用 `bailong-codex-watch.service`，立即开始监听，并在下次登录图形桌面时自动恢复。监听器每两秒识别当前用户的 Codex Electron 桌面主进程，忽略普通 CLI 与 Electron 子进程；开启时若 Codex 已运行，也会尝试启动桌宠。

每次新的 Codex 进程会话只触发一次，同一会话中手动退出桌宠不会反复拉起。桌宠仍受数据目录单实例锁保护，与普通开机自启动同时开启不会产生重复界面。“随 Codex 关闭”在源码中已单独接入，不因启用启动监听而自动开启退出联动；linux-preview.2 包尚不包含退出联动。

监听器不创建 Qt GUI、不加载人物素材或查询额度；源码入口不导入 Qt，冻结包的 PyInstaller 钩子会预载 QtCore。触发时通过独立临时用户服务 `bailong-codex-pet.service` 启动桌宠；关闭开关会取消监听器的自启动并立即停止监听，不关闭已运行的桌宠。监听与桌宠服务都随图形会话结束而停止，不改动 Codex 配置或启动器。

```sh
systemctl --user status bailong-codex-watch.service
journalctl --user -u bailong-codex-watch.service -b
```

108 项适配/公告刷新回归通过。本机用隔离数据目录确认真实 Codex 检测及桌宠启动、手动停止桌宠后不重新拉起、停止监听后桌宠保留；测试服务已清理，未开启日常监听。5 秒短采样监听器单核 CPU 1.2%、RSS 18.3 MiB，未加载 Qt；这不是长期平均。未关闭用户的 Codex 来做完整退出再打开验收，会话重开逻辑由原 LaunchGate 回归覆盖；新 AppImage 与重新登录仍需后续验收。


## 随 Codex 关闭与会话跳转

以下两项已进入 v1.2.1-linux-preview.3，旧 linux-preview.2 包不包含；niri 与 KDE 共用接入代码，Windows 入口不变。

- **随 Codex 关闭**：在设置 → Codex 中勾选“Codex 桌面端关闭后退出桌宠”。沿用原 ExitGate：本次运行先观察到当前用户的 Codex 桌面主进程，再每两秒检测一次，连续三次明确不存在才正常退出（约 4–6 秒）。未知权限状态中断退出计数，短暂退出后恢复则重新计数。未打开过 Codex 时不会自行退出；只关窗口但主进程仍驻留时不会退出。开关默认值和保存方式不变，与两个启动开关独立；关闭选项后不扫描进程。检测在原后台线程中执行。
- **会话跳转**：点击任务名称时，复用原会话 ID 校验及异步导航队列，通过 `xdg-open codex://threads/<UUID>` 打开对应任务。“打开 Codex”按钮使用 `codex://launch` 唤起桌面。宿主需 `xdg-utils`，且 Codex 安装需注册 `x-scheme-handler/codex`；可用 `xdg-mime query default x-scheme-handler/codex` 检查。程序不会修改协议注册。无处理器、打开失败或超时时由原气泡提示，不回退打开其他会话。派发成功不作为已读证据，仍等待实际已读状态。

本机用户已确认两个跳转入口正常。退出联动使用独立桌宠数据目录及合成桌面进程验证：保留真实 Linux 进程识别器，只过滤到测试 PID，终止该测试进程后 4.16 秒正常退出，状态锁释放、设置保留；未关闭用户实际 Codex，不将合成退出视为完整人工验收。117 项 Linux/共享逻辑回归和 actionlint 通过，覆盖未见过启动、未知状态、短暂消失、选项关闭、协议失败、异步 GUI 处理及点击后未读保留。本轮未重建 AppImage，也未在 KDE 实机重复验收。
